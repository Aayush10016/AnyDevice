# Security policy

Discovery/workspace development builds do not authorize collection from container siblings or ancestor relationship lists. Candidate membership is checked against freshly inspected native instance IDs; the helper still requires a unique mapped instance/kind and filters hDevice/type. Ambiguous receiver or duplicate-interface mapping remains a limitation. Focus/navigation/reset cancellation reasons survive queued events and finalization, and creator/executable ownership and foreground checks remain enforced.

Automatic discovery/diagnostics are read-only. The audio milestone adds explicitly consented bounded streams and a narrow approved endpoint mute provider; see [architecture and limits](docs/AUDIO-DIAGNOSTIC-ARCHITECTURE.md). There are no driver/registry/firmware modifications, arbitrary shell execution, privileged repairs or auto-elevation. Treat all Windows device metadata as untrusted. React renders it as text; fixed adapters pass instance IDs as parameters and never evaluate them as code.

Please report vulnerabilities privately through GitHub's private vulnerability reporting on Aayush10016/AnyDevice once enabled. Until that feature is configured, do not disclose secrets or hardware identifiers in public issues. No dedicated security email address is configured.

Only the latest validated release will receive fixes; no stable release has completed every manual validation gate. Dependencies should be reviewed before release. Unsigned builds do not have trusted publisher verification. Do not mistake a process-launch smoke test for comprehensive security or hardware validation.

0.2.0 native collection uses documented read-only Configuration Manager APIs in a child of the same executable with two fixed allowed scopes. The child is hidden, has no stdin, and is terminated on cancellation, timeout or stdout overflow. Optional fallback remains fixed and metadata is never executed. Raw sample imports allow only three byte-sample extensions and 1 MiB; no imported binary or generated code is executed. Exports validate JSON schemas in the frontend and envelopes/size in Rust, then use a native save dialog. Paths are not constructed from metadata. Native properties and entire inventories are bounded. Real inventories/identifiers must never enter public workflow logs or artifacts.

Strict production CSP remains enabled. Standalone schema validators replace runtime Ajv compilation, and a regression forbids string/wasm code generation. Native presence is a typed Windows Boolean; explicit absent nodes are excluded without implying defects. A non-elevated real-host test succeeded. Installation/launch and VM checks do not constitute a comprehensive security audit or packaged UI/export verification.

The input milestone uses an isolated same-executable session process with exact native instance mapping and fixed mouse/keyboard/X modes. No hooks, kernel driver, HID output transfers or arbitrary shell evaluation. Input streams have duration/packet/frame/byte/history limits; native foreground checks precede selected payload decoding. Stop kills/waits; discard clears final session memory. A successful registration or synthetic event decoder test is not physical input validation.

Audio capture/playback require per-endpoint UI consent plus native approval, actual-parent/matching-image ownership and foreground checks. Temporary capture buffers are reduced to aggregate numbers; no PCM is saved/exported/uploaded. Hidden bounded helpers are terminated on cancellation/timeout and protected by Windows kill-on-job-close jobs. HID inspection asks only for bounded Windows preparsed capabilities and never transfers device reports. Mute changes require a fresh exact proposal, explicit approval, expected-state recheck and readback; rollback requires separate approval and an unchanged verified state. External Windows setting changes can race the non-atomic check/write. No automatic repair or hardware-health claim is permitted. Physical privacy-indicator/cleanup and setting rollback still need user-operated acceptance.
