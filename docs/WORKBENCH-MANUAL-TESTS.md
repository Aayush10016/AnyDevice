# User-operated Device Workbench acceptance

These procedures have NOT yet been performed on the user's physical mouse/keyboard. Do not treat automated fixtures, endpoint enumeration or registration probes as physical acceptance. No X-switch or lighting fault is reproduced/fixed.

1. Open the new milestone candidate, use native all-present-PnP scan, select your observed mouse/receiver or keyboard node. Inspect parent/container evidence and the mapped input collections. If multiple endpoints exist, choose one and record why; a Logitech name or matching VID/PID alone is insufficient. The radio mouse and receiver remain distinct physical objects.
2. In Live Tests, explicitly Start Test with AnyDevice focused. Mouse: move, click left/right/middle, use supported extra buttons, scroll up/down and horizontal where supported. Record the latest event/time, counts, signed deltas and held/released states. Native event presence does not establish sensor/wheel accuracy.
3. Stop: wait for cleanup confirmed. Reset: counters clear, no session active, prior summaries remain. Start again then change workbench tab, close the workbench, switch application focus and safely disconnect the selected endpoint in separate sessions. Confirm collection stops and no later keyboard/mouse actions are logged. Do not remove storage or disturb another user's equipment as a test.
4. Keyboard: use ordinary test keys only, never passwords/private text. Observe down/up, per-key counts, repeat/held states, modifiers and simultaneous keys in the generic layout. Verify another keyboard/trackpad does not increment the selected collection. Generic layout/scancode behavior may differ by model/layout.
5. X scenario: choose X-only, record physical-attempt estimate and test conditions before starting; press and release X repeatedly. Stop before entering additional text. Compare non-repeat downs/up/repeats with reported attempts. Record uncertainty from focus, attribution, counting and event handling; do not conclude switch failure from a mismatch. Repeat the same procedure; no repair has been applied.
6. Report a Problem: record exact X/LED symptoms and visible observations as user reports. Confirm software states lighting control/feedback unsupported, no commands sent and no claim of LED function/fix.
7. History & export: prepare raw and sanitized previews; verify no ordered key-event history or typed text is exported. Sanitized identities/symptoms/conditions/attempts are withheld; aggregate key codes/counts/times remain. Save/cancel through the native dialog; test unwritable destination feedback. Export before closing, as workbench history is volatile.
8. Record each criterion as Passed/Failed/Blocked/Not tested with actual endpoint attribution, time, test conditions, observed response and remaining uncertainty. Complete packaged keyboard/accessibility/DPI/clean-machine install/upgrade/signing before stable release.
