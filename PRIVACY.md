# Privacy

No telemetry, analytics, external AI, uploads or accounts. Core scans run offline using Windows. Current/prior inventories and recent activity stay in application memory and disappear when closed. Appearance and sanitization preferences are stored in local WebView storage. Save paths are displayed only in the current session. No background scans or automatic hardware-report persistence.

Report export opens a native file dialog and writes only the report the user reviewed. Raw reports can contain hardware/instance IDs, serial-like values, device names, manufacturers, parents, locations and error details. Default sanitized export removes free-text metadata, identifiers, hardware IDs and detailed error messages everywhere, including prior scans and findings; replaces references with report-local aliases; retains exact VID/PID, collection times and normalized status/problem codes. These remaining values may still identify device models or timing. Sanitization is a sharing aid, not a guarantee of anonymity. Review the preview before sharing.

No report is automatically uploaded to GitHub. Test fixtures and example reports are synthetic. Do not attach raw production reports to public issues. Windows, WebView2 or operating-system components may have their own policies independent of AnyDevice.

Investigation captures and raw imported samples are held only in memory, with explicit clearing and export. No automatic persistent investigation store is enabled. Sanitized investigations remove user annotations and remap all captures/comparison references with session-local aliases. Binary analysis exports never include raw bytes; sanitized analysis also withholds filenames, SHA-256 fingerprints and hypothesis labels. Offsets, lengths, differences and timestamps can remain sensitive. Broader PnP mode can expose more system-node metadata; it collects no volume contents, audio/video streams or unrelated personal information.

Export validators are generated at build time from repository-owned schemas and operate locally without eval or an external validation service. Real hardware integration evidence is kept outside the public repository; only generic counts/capability results are documented.

Device Workbench input tests are explicit, selected-collection and foreground-only. Leaving Live Tests, losing application focus or closing the workbench stops collection. Key codes/scancodes are observed, never translated into typed characters. X-only discards other keys. Recent input history is bounded/volatile; closing the workbench cancels and discards the native snapshot. Exports contain aggregates, not ordered key-event histories or typed text. Sanitization removes identity, exact symptoms/conditions and reported attempts; aggregate codes/counts/timing remain sensitive. No input collector runs at startup or during ordinary inventory inspection.
